# Lessons index

Use this layout once `research/lessons-learned.md` grows past about 150 lines of lessons or 16,000 characters.
Then `lessons-learned.md` becomes a short stub that points here, and the lessons move into one file per area.

How to use (read this file first; then open only the 1-3 area files your decision needs):
1. Grep this file for the trigger words of your decision (buy, price, launch, hire, agent, contract…).
2. Open the area file named above the hit line; jump to the lesson with Grep `^### L-004`.
3. In your gate or brief, quote 1-3 lessons by ID and their Action line; say honoured or skipped, and why.
4. If nothing applies, write `uses: none (no lesson applies)`. That is a valid answer.

Writer: the keeper only. Status: watch → identified → actioned → embedded → verified (or retired). Rung R0-R5.
Field legend, grades and ladders: see the "How lessons are written" part of the single-file starter.
Caps: this index ≤150 lines and ≤15,000 characters (hard cap 200 lines / 18,000). An area file ≤16,000 characters; past that, split it by sub-topic at the next touch. IDs never change on a split.
