## Product

### L-003 (EXAMPLE) A thin wrapper around one model needs its own data or workflow to survive
- Observation: Tool A (a writing assistant) lost most of its users within months when the model provider shipped the same feature for free. Tool B, which stored each customer's own templates and approvals, kept its users.
- Cause: when the only value is the model's output, the provider can copy it. Customers stay for their own data, integrations and habits.
- Action: before building a feature, write down what the user would lose by leaving (their data, history, team workflow). If the answer is "nothing", do not build it as the core.

## Pricing and costs

### L-002 (EXAMPLE) Price from your API cost per active user, not from a competitor's price
- Observation: Tool C copied a competitor's $10/month price. Its heaviest 10% of users cost more in API calls than they paid.
- Cause: AI tools have a variable cost per use, unlike classic software. Heavy users can turn the margin negative.
- Action: measure API cost per active user in the beta. Set the price at a margin target, and add usage limits or tiers for heavy users before launch.

## Marketing and launch

### L-001 (EXAMPLE) Build a waitlist before launch; launch-day users come from your own list
- Observation: tools that launched on Product Hunt without an audience got a one-day spike, then almost no signups. Tools with a waitlist of a few thousand people converted part of it on day one.
- Cause: launch platforms send short-lived traffic. Lasting early users come from people who already asked to be told.
- Action: start a waitlist page now. Set a target size (e.g. 500 people) that must be reached before you set a launch date.
